# 标书审查（Bid / Tender Response Review）
针对中文招投标场景（公开招标 / 竞争性磋商 / 询价等），对「招标文件 + 一份或多份响应（投标）文件」做符合性与废标风险审查，产出结构化、可交付的审查报告。本技能由一次真实的多响应文件审查（竞争性磋商、3 份响应文件、65 万预算）沉淀而成，内置该次审查验证有效的并行子代理工作流与图片证据处理规则。
## 何时使用
- 用户给出 **1 个招标文件**（采购文件 / 磋商文件）和 **1~N 个响应文件**（投标 / 磋商响应），要求「检查 / 审查 / 核对 / 找问题 / 看会不会废标 / 符合性审查」。
- 适用产物：废标（无效响应）项矩阵、资格性与符合性核查、重点（★/▲）条款响应对比、技术参数证明材料汇总对比（含出处）、分级问题清单（🔴废标风险 / 🟠严重 / 🟡一般 / 🟢建议）、**每份响应独立 HTML 分析报告 + 汇总 HTML 报告**。
## 核心工作流（6 步）
1. **抽取文本**（按扩展名路由，统一输出到工作区 `output/`）：
   - 输入 = **1 个招标文件 + 0~N 份补遗/澄清公告 + 1~N 份响应文件**，全部抽取：
     - .docx → `scripts/extract_docx.py`（加 `--extract-images` 导出图片证据）
     - .pdf  → `scripts/extract_pdf.py`（保留标题层级+表格，导出图片）
     - .doc  → `scripts/extract_doc_text.py`（olefile 纯文本，无图片）
   - 招标文件存 `output/招标文件.md`；补遗依次存 `output/补遗1.md`、`output/补遗2.md`…；响应文件存 `output/响应文件_XX.md`。
   - 抽取后在含图片处插入 `[IMAGE: images/<safe>/img_NNN.png]` 标记（`<safe>` = 源文件名stem + 源文件绝对路径md5前6位，按源文件哈希分目录；详见铁律 2）。
2. **提取审查基准（含补遗合并）**：
   - 先跑机械装配：`.venv\Scripts\python.exe scripts/merge_addenda.py --tender output/招标文件.md --addenda output/补遗1.md output/补遗2.md --out output/审查基准_合并输入.md`
     得到【补遗清单】+【拼接全文】+【疑似冲突条款清单】。
   - 精读 招标文件 + 各补遗，按 `references/review-baseline-template.md` 提取：项目信息、废标（无效响应）条款清单、资格性条件、符合性/形式要求、采购需求与重点（★/▲）条款、评分标准、偏离表要求，**并按 §五『技术参数响应证明材料要求汇总表』提取（无论是否 ★/▲，标注出处）**；**同时提取 §七·五『招标文件明示允许/豁免条款清单』**——凡招标文件明示"视为满足 / 视为完全响应 / 无需提供 / 不构成无效 / 允许空白"等形式，逐字摘录原文+出处，作为子代理与终审"不得列为风险"的权威清单。写入 `output/审查基准.md`。
   - 冲突条款以「后发布者（补遗/澄清）优先」裁决，写入基准的「补遗与澄清清单」字段。
2.5 **图片证据目检**（消除"无法判定"盲区）：
   对 `output/images/<safe>/` 下每张 `img_NNN.png`（`<safe>` = 源文件名stem + 源文件绝对路径md5前6位，按源文件哈希分目录），用 Read 工具查看，对照 checklist 相关条目判定：签章是否齐全真实、证书/执照是否在有效期内、信用截图是否有水印或 PS 痕迹、业绩合同是否缺签名。判读结论写入子代理报告，并标注来源文件名（如 `images/<safe>/img_003.png`）。
3. **多份并行审查**：对 N 份响应文件，**每份启动一个独立子代理**（Agent 工具，general-purpose）并行审查，对照审查基准产出逐份报告（`output/子代理报告_XX.md`）。子代理提示词模板见下方「子代理提示词模板」。
3.5 **机械核查**（不让 LLM 心算数字）：
   限价取自审查基准 → 跑：
     `.venv\Scripts\python.exe scripts/verify_prices.py --baseline output/审查基准.md --doc output/<响应文件>.md`
     `.venv\Scripts\python.exe scripts/consistency_check.py output/*.md`
     `.venv\Scripts\python.exe scripts/crossref_check.py output/响应文件_*.md`
   输出明细合计=一览表、总报价≤限价、大小写一致、公司名/型号/日期格式差异，以及 `output/机检_内容一致性.md`（**单文档内容前后一致/矛盾核查**：分项表字段错位=品牌/产地/型号串行、跨位置敏感字段冲突=编号/投标主体/法定代表人/金额大小写等）；子代理报告须引用机检结论，数字类结论以机检为准。
4. **终审汇总**：终审前先跑评分估算（基于审查基准评分标准 + 各响应文件抽取文本）：
     `.venv\Scripts\python.exe scripts/score_estimate.py --baseline output/审查基准.md --docs output/响应文件_01.md output/响应文件_02.md [--out output/评分估算.md]`
     读取其「得分对比」与「零分项预警」，纳入终审报告对应章节。
   随后主代理读取所有子代理报告、机检与评分估算结果，交叉核对废标项触及情况，去重定级，按 `references/report-template.md` 产出 `output/终审汇总报告.md`。对全部 🔴 项抽查回读 `output/` 原文验证，位置不可核查者降级为无法判定。
   **终审交叉校验（防误判）**：对照基准 §七·五『明示允许/豁免条款清单』逐条复核所有子代理报告的 🔴/🟠 风险项（可跑 `scripts/audit_risks.py --baseline output/审查基准.md --reports output/子代理报告_*.md` 机械列出"允许清单 vs 风险项"对照表）。凡命中清单且无清单外实质问题者，一律剔除或降级；无招标文件条款依据的风险项降为 🟢 建议或删除。
5. **HTML 呈现**（每份独立报告 + 汇总报告，均脚本渲染）：
   - 5a **每份响应独立报告**：主代理读 `output/子代理报告_XX.md`，按 `assets/file-report-template.html` 的 15 个 token 组装 `output/report_data_XX.json`（键=token，值=HTML 片段），调用：
     `.venv\Scripts\python.exe scripts/render_report.py --template assets/file-report-template.html --data output/report_data_XX.json --out output/子代理报告_XX.html [--strict]`
   - 5b **汇总报告**：把终审报告各区块拼为 HTML 片段，写入 `output/report_data.json`（须含 `assets/report-template.html` 全部 19 个 token，含证明材料汇总 TECH_PROOF_TABLE / TECH_PROOF_NOTES），调用：
     `.venv\Scripts\python.exe scripts/render_report.py --template assets/report-template.html --data output/report_data.json --out output/终审汇总报告.html [--strict]`
   脚本替换全部 `{{token}}`；若有残留 `{{}}` 会告警（`--strict` 时退出非 0）。
   兜底（脚本异常时）：仍按模板视觉风格手工替换后 `grep -n "{{" output/*.html` 校验为 0 再交付。
6. **交付与说明**：present 报告，并明确「图片证据 / 签章原件无法由文本判定」的限制与免责。
## 四条铁律（来自真实审查经验，务必遵守）
- **铁律 1 — 废标优先**：先查废标（无效响应）条款，再查评分。废标项是零分风险，优先级高于任何得分点。
- **铁律 2 — 图片证据不可臆断**：docx 中营业执照、证书、信用截图、软件界面、合同、PPT、签字盖章等常以**图片**存在，文本抽取读不到（抽取脚本已将其导出为 `output/images/<safe>/img_NNN.png`（按源文件哈希分目录）并在正文插入 `[IMAGE: ...]` 标记）。凡涉及图片证据的条款，判定写「**无法判定 / 需核对原件**」（图片目检见第 2.5 步），**既不等于已满足也不等于未满足**；严禁因「文件里有这一章」就默认合规。
- **铁律 3 — 诚信红线**：重点核对「偏离表」声明与正文参数是否一致。若偏离表写「无偏离」但正文参数超出/低于招标要求（如速度上限超、处理器谱系不符），必须作为 **🟠 诚信风险** 单列，建议在磋商/澄清环节书面质询。
- **铁律 4 — 招标文件明示优先**：招标文件**明示允许/豁免**的形式（如偏离表「空白/只填"无"=完全响应」、信用承诺函替代证明材料等，见基准 §七·五 明示允许清单）**不得列为风险/问题**；任何 🔴/🟠 风险结论必须有招标文件具体条款依据；通用审查经验/行业惯例（如"空白偏离表有澄清风险"）不得凌驾于招标文件明示条款。注意：**形式合规 ≠ 实质响应**——偏离表空白=完全响应仅解决"形式合规"，仍须按铁律 3 核对正文参数是否真实达标（正文参数低于招标要求仍属实质负偏离/诚信风险）。
## 价格与一致性核查（通用，先做）
- 总报价 ≤ 最高限价（预算）；超限即废标。
- 报价明细表各行合计 = 报价一览表总价；不一致即废标（常见「格式四注」）。
- 报价有效期 ≥ 要求天数（如 45 天）。
- 不接受联合体时，不得出现联合体声明。
- 保证金：若要求而未提交 → 废标。
- 上述数字类结论以第 3.5 步机检脚本输出为准，不靠 LLM 心算。
## 子代理提示词模板（复制后替换占位符）
> 你是一名严谨的招投标合规审查专家。独立审查响应文件 `{{响应文件文本路径}}`，对照审查基准 `{{审查基准路径}}`（含废标清单、资格/形式要求、重点条款、评分标准、**明示允许/豁免条款清单 §七·五**）。
> 步骤：1) 读审查基准建立标准；2) 完整读响应文件（图片处先按 `[IMAGE: ...]` 标记用 Read 工具目检原件，仍不可判定者标注「需核对原件」，不得臆断已满足）；3) 按 7 项结构产出报告：
> ① 废标项逐条核查表（触及/未触及/无法判定 + 证据位置与说明）；
> ② 资格性与形式要求逐条核查；
> ③ 采购需求响应逐项核查（重点标 ★/▲，指出材料是否提供）；
> ③·五 技术参数响应证明材料核查：对照基准『证明材料要求汇总表』逐项判定 提供/未提供/图片需核对（图片按铁律2 不臆断），给出 [技术参数/条款|要求材料|本文件是否提供|证据位置/出处]；
> ④ 评分项逐项估分（对照基准「评分标准」表）：对每项给出 [分项 | 估分(保守) | 是否可能0分 | 依据/不确定性]；
>    客观项有材料按保守成数估、无材料记0；主观项给区间并标注不确定性高；
>    证据为图片者写「需核对原件」，不得臆断分值（定量得分对比表由 score_estimate.py 机算，见第4步）。
> ⑤ 价格合规（≤限价、明细合计=一览表，引用机检结果）；
> ⑤·五 内容一致性/前后矛盾核查：引用机检 `output/机检_内容一致性.md` 结论，并对照该份响应文件的采购清单/报价明细/声明处原文，逐一复核每条疑似项，判定为"录入错列 / 贴牌套牌 / 独立品牌异地代工（正常）/ 跨版本串文件 / 无问题"，把确认或高度可疑的项并入分级问题清单（🔴/🟠/🟡），并在报告说明判定依据；
> ⑥ 分级问题清单（🔴/🟠/🟡/🟢，每条含 位置 / 证据 / 风险 / 建议，🔴/🟠 须含【原文】+【招标文件条款号】）；
> ⑦ 总体结论 + 截止前最紧急整改项。
> 要求：每条 🔴/🟠 问题必须含【原文】摘录、【招标文件条款号】与【位置：第X节约Y页】三要素（位置来自抽取标记）；基于证据、不臆造；用 Write 写入 `{{输出路径}}`，回复摘要 ≤800 字。
> 硬性规则（违反即视为审查失败）：
> R1 明示允许不列为风险：凡审查基准 §七·五『明示允许/豁免条款清单』覆盖的情形（如偏离表空白=完全响应），一律判定合规/未触及，不得列为风险或问题。
> R2 风险必须有条款依据：任何 🔴/🟠 风险结论必须引用招标文件具体条款号（如「格式四注」「供应商须知前附表第X项」）作为依据；无条款依据的不得列为风险，最多降为 🟢 建议。
> R3 明示条款优先于通用经验：通用审查经验/行业惯例（如"空白偏离表有澄清风险"）不得凌驾于招标文件明示条款；招标文件明示允许的形式不构成风险。
> R4 形式合规≠实质响应：偏离表空白=完全响应仅解决"形式合规"，仍须按铁律 3 核对正文参数是否真实达标（正文参数低于招标要求仍属实质负偏离/诚信风险）。
> R5 内容一致性以机检为主：凡"内容前后矛盾/字段串行/跨位置信息冲突"（品牌·产地·型号错位链、编号·投标主体·法定代表人·金额大小写跨位置不一致）一律先读 `output/机检_内容一致性.md`，机械命中仅作提示不自动判违规；不许凭心算/印象下这类结论。机检命中的每一项须人工对照原文判定去向，并把高度可疑项作为独立风险点写入报告。
## 详细审查清单
完整核查项（废标/资格/符合性/重点条款/技术/诚信/文档完整性/常见红旗）见 `references/checklist.md`，审查时逐项对照，避免遗漏。
## 依赖与安装
首次使用请建虚拟环境并安装（在 skill 目录下）：
  ```bat
  python -m venv .venv
  .venv\Scripts\Activate.ps1
  pip install --upgrade pip
  pip install -r requirements.txt
  ```
> **跨平台**：上文 `.venv\Scripts\python.exe` 为 Windows 示例调用；Linux/macOS 用 `.venv/bin/python`（激活后直接 `python scripts/xxx.py` 亦可）。所有脚本全部相对路径 + argparse 参数化，无硬编码绝对路径，`requirements.txt` 已列齐依赖，可整体迁移到任意设备（迁移时删除 `.venv/` 与 `__pycache__/`，目标机重建即可，见 README.md）。
调用脚本统一用当前 venv 解释器：`.venv\Scripts\python.exe scripts\extract_docx.py ...` 或激活后 `python scripts\extract_docx.py ...`。
依赖：
- `python-docx`（.docx 抽取，`scripts/extract_docx.py`）
- `olefile`（.doc 纯文本，`scripts/extract_doc_text.py`）
- `pdfplumber`（.pdf 抽取，`scripts/extract_pdf.py`）
## 局限与免责
- 本技能基于文本抽取并**导出图片证据供目检**，但**不含图片 OCR / 视觉鉴伪**。最终废标与评分以磋商/评标小组对盖章正本及随附原件/图片的认定为准。
- 电子标（CA 数字证书、文件加密/解密、平台上传回执、电子签章完整性）的**有效性**以平台/CA 机构认定为准，本技能仅做文件层核查项提示。
- 评分估算为**保守辅助估分**（客观项按材料保守成数、主观项给区间、缺失记0、图片记?），非评标结论，最终得分以评标/磋商小组为准。
- 补遗/澄清的语义合并（哪条条款被修改、新文本为何）由 LLM 在基准提取时按「后发优先」裁决；`merge_addenda.py` 仅提供机械装配与冲突提醒，不替代法律判断。
- 本报告为合规审查辅助意见，不构成法律意见；checklist 中的「依据：…」为常见条文锚定（以现行有效版本为准），非法律意见。
