# 标书审查 — 经验教训库（lessons-learned）
> 每次审查后把用户 / 招投标人员的反馈沉淀为案例，持续改进审查准确度。
> 案例格式：误判描述 / 根因 / 修正规则 / 对应 skill 改动。

## 案例 1：技术偏离表「空白=完全响应」被误判为澄清风险（2026-08-18）
- **误判描述**：三份响应文件技术偏离表均为空白+笼统"完全响应"，子代理与终审将其列为"评审时存在被要求逐项澄清的裁量风险"。
- **招标文件原文**（格式四注）：注：1、若本表空白或只填写"无"或未列明有负偏离的，均视为完全响应采购文件所有技术要求，不提供此表作无效响应处理。
- **根因**：
  1. 基准虽提取了注1规则，但未标注为"明示允许/豁免"权威清单，权威性不足，子代理未将其视为约束；
  2. 子代理提示词未强制"明示允许不得列为风险"，子代理凭通用审查经验（行业常见提示"空白偏离表有澄清风险"）凌驾于招标文件明示条款；
  3. 终审无"风险项 vs 明示允许清单"交叉校验，误判一路贯通到最终报告。
- **修正规则**：招标文件明示允许的形式不得列为风险（铁律4）；风险必须有招标文件条款依据；形式合规 ≠ 实质响应，仍须核对正文参数是否真实达标。
- **对应 skill 改动**：新增铁律4；基准模板新增 §七·五 明示允许/豁免条款清单；子代理提示词新增 R1-R4 硬性规则；终审新增交叉校验步骤（audit_risks.py）；checklist 第3/7节补充明示允许判定规则。

## 案例 2：采购清单"产品信息与产地等串行"——升级为通用内容一致性核查能力（2026-08-19）
- **误判/遗漏描述**：双思响应文件采购清单中品牌/产地/型号整体错位（如"遇物→标杆→凯祥"循环错位、南京制造商产地写成深圳、零百制造商标"零百"写成"遇物"），招投标人员人工才发现。旧 skill 无任何脚本或提示词能系统核查"内容前后不一致/矛盾"这一类问题。
- **根因**：
  1. 旧 skill 的一致性机检（consistency_check.py）只做"跨文件"比对（公司名/型号变体/日期格式），**不查单文档内部**表字段错位与跨位置字段冲突；
  2. 表内字段（品牌/产地/型号/制造商）各自孤立被比对招标清单，缺乏"同表内互核"规则，错位链被当成多个独立小差异，不被识别为移位；
  3. 无对应子代理提示词 / checklist 项，子代理不会主动排查"字段串行"这类非废标但高影响的录入/诚信问题。
- **修正规则**：单文档内容一致性是一类可机械判定的矛盾（表字段错位链 + 跨位置敏感字段冲突），不是孤立 bug。建立"机检规则判定 + 人工复核去向"的双层能力：脚本只做机械提示（品牌可为独立商标、产地可异地代工，命中≠违规），子代理/终审把高度可疑项并入分级问题清单，并区分"录入错列（改表）"与"贴牌套牌/串文件（可能触及实质响应/废标）"。
- **对应 skill 改动**：新增 scripts/crossref_check.py（V2.3.0，整合表字段错位检测与跨位置字段冲突检测，替代临时 field_misalign_check.py，输出 `output/机检_内容一致性.md`）；SKILL.md 第 3.5 步机械核查新增该脚本、子代理提示词新增 ⑤·五 与硬性规则 R5；checklist 新增第 10 节"内容一致性/前后矛盾"。
