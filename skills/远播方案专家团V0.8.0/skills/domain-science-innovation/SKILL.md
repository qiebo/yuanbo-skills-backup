# Domain · 科创 / 科学教育

## 1. 核心设计链
优先使用：

`学生能力 → 学习任务/课程 → 真实项目 → 资源/设备/数据 → 空间 → 成果与运行`

设备是实现学习任务的资源，不是方案主角。

## 2. 学段差异
### 初中
- 兴趣与问题意识；
- 基础工具和规范操作；
- 可完成、可展示的短周期项目；
- 以直观实验、设计制作、数据启蒙为主。

### 高中
- 研究问题定义与实验设计；
- 数据采集、建模与解释；
- 工程设计、制造、测试、迭代；
- 跨学科项目、研究型学习、课题与高阶成果。

不要只把高中课程写成“初中内容更难一点”。

## 3. 课程/项目设计
每个核心模块至少回答：
- 学生为什么学；
- 学生具体做什么；
- 用什么工具/数据/设备；
- 得到什么可观察成果；
- 如何与下一阶段或其他空间连接。

是否分“普及/进阶/研究”取决于真实对象和运行机制，不强制三级。

## 4. 多空间项目
实验室集群不能只是主题并列。至少找出一种真实协同：
- 公共方法底座；
- 原型制作/测试共享平台；
- 跨实验室项目接力；
- 数据/设备/展示资源共享。

例如：真实问题 → 数据分析 → 方案设计 → 原型制作 → 测试验证 → 成果展示。不是要求所有空间固定占一个阶段，而是用共同项目逻辑把空间连起来。

## 5. 空间关注
- 实验/制造动线；
- 供电、通风、除尘、防护、储物；
- 集中教学与小组项目切换；
- 原型制造与测试隔离；
- 作品展示和项目答辩；
- 设备使用权限与安全准入。

## 6. 成果
成果可以包括实验记录、工程文档、数据模型、实物原型、研究报告、展示答辩、课程作品、校内课题等。赛事只是可能出口，不能成为所有项目的唯一价值证明。
