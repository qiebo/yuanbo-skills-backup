# Changelog

## V2.0

- 将超长单体提示词拆分为调度层、规则层、模板层、校验层和渲染层；
- 新增事实证据台账、需求响应矩阵、课程设备空间映射、实施验收矩阵；
- 删除静态赛事状态结论，改为项目级动态核验；
- 将“首个/领先”改为高风险主张；
- 将固定三方自评改为确定性校验 + 文类自适应专家评审；
- 删除直接 XML 字符串替换作为标准修改流程；
- 用 Pandoc 解析 Markdown，避免表格静默丢失；
- 新增 Word 渲染、反馈提取、版本对比和流水线工具；
- Word 构建在缺失源文件或工具时显式失败，不回退到示例方案。

## V2.1（2026-07-27，基于华南师大附中智慧能源实验室项目复盘）

按"先逐条确认、再修改"的方式，根据一次完整售前方案过程暴露的通用问题优化：

- **节点确认机制**：新增 SKILL.md §2.4，支持 `confirmation_mode`（full/core/each），默认在关键产物给出摘要请用户确认；workflows 各阶段末增加"输出摘要请确认"步骤；阶段 0 "直接继续"改为受确认模式约束。
- **构建可靠性**：build_docx.py 新增 `--overwrite`（覆盖写同名输出并自动备份旧版为 `_备份_时间戳`），消除"时间戳→后处理→改名"的脆弱流程。
- **字体与缩进内建**：build_docx.py 集成 `output.font`（默认微软雅黑）与 `output.first_line_indent`（默认 2 字符），统一应用到正文、表格单元格与页眉页脚（此前表格单元格会掉字体，且需临时脚本后处理）。
- **渲染降级**：render_review.py 在 LibreOffice/soffice 不可用时自动执行结构化降级验收（非视觉渲染），并标注须人工复核版式。
- **文档完整性硬门槛**：validate_project.py 新增 STAGE_DOC_EMPTY（01/02 空模板→error）与 STAGE_DOC_THIN（其余阶段文档偏薄→warning）。
- **封面标签可配**：project.yaml `confidentiality` 改为按交付对象选择、可留空不显示（默认客户交流版，替代固定"内部资料"）。
- **外部权威文件**：新增 `project.external_authoritative`，SKILL.md §2.2 明确其作为设备命名/价格唯一来源、Word 仅概念引用、旧清单标注"参考样例/作废"。
- **客户交付红线**：writing_guide.md 增补"面向客户的交付红线"（学校文化自然融入不贴标签、参考图不提他校、无内部口径、价格集中归预算章、整段叙述为主）。
- **内容充实与借鉴**：writing_guide.md 新增第 10 节，明确"借充实度不借格式与名称、不引入未核实事实"。

## V2.2（2026-07-27，固化 grill-me 需求澄清机制）

将全局"先问清需求再执行"规则固化进 skill，作为无条件强制铁律：

- **需求澄清机制（grill-me）**：SKILL.md 新增 §2.4——任何项目开始执行前必须先完成 grill-me 式澄清，一次一问、至 95% 把握才动手；阶段 0 强制澄清，后续阶段缺漏才问。原"节点确认机制"顺延为 §2.5，并新增输入端/输出端交叉引用。
- **workflow 加澄清步骤**：workflows/01 第 2 步新增 grill-me 强制澄清（含澄清要点清单），后续步骤相应顺延，并补"后续阶段缺漏才问"说明；§2.4→§2.5 引用同步改号。
- **新增 references/grill_me_guide.md**：适用判定、一次一问核心规则、从方向到边界的追问策略、话术示例、95% 把握判定标准、与节点确认机制的配合关系；SKILL.md §8 资源索引已登记。
