# Changelog

## v2.1（2026-08-02，当前发布版本）

> 本版本即当前对外发布版本 **v2.1**，整合了此前内部迭代 V2.0（架构重构）、V2.1（节点确认）、V2.2（grill-me 澄清机制）、V2.3（正式方案去 AI 味）、V2.4（writing-great-skills 提示词精炼）的全部能力。下方 V2.0 / V2.1 / V2.2 / V2.3 为早期开发记录，保留备查。

目标：用 Matt Pocock `writing-great-skills` 的核心杠杆（预测性、信息层级、渐进披露、剪枝、失败模式防御）提升 SKILL.md 的可预期性与可读性，不改变任何业务规则与阶段语义。

- **去重 / 单一内容源（Duplication → Single Source of Truth）**：阶段 6.5 原内联 8 类检测清单（最毒句式/客套开场结尾/模板过渡/模糊限定/官腔空话/无证据强词/空泛修饰/机械化连接词）与 `references/formal_dereification.md` §2 完全重复。改为仅在阶段 6.5 保留一句原则 + 指向 reference 的指针，明细以 reference 文件为唯一权威源，本阶段不重复罗列。
- **补强完成判定（Premature Completion 防御）**：阶段 5「正文撰写」原先只有 8 条要求、无明确"完成"标准。新增**完成判定**：每章均可回链需求响应矩阵中至少一条具体需求、全篇无挂起待确认标记、每个结论力度不超过证据等级，方可进入阶段 6。
- **正面化禁止（Negation 防御）**：§2.1 标题由"禁止静默补全"改为主动表述"事实须有可靠依据"，开篇句正面陈述"写入确定事实前须已有可靠依据"，保留"禁止静默补全"作为硬护栏并配正面动作（三种处理方式）。
- **剪枝（No-Op / Sediment）**：合并冗余表述，SKILL.md 由 399 行精简至 390 行，顶部信息层级更清晰、易维护。
- **验证**：YAML frontmatter 仍合法；`validate_project.py` 仍可正常运行（样例预期 2 error / 1 warning 与本改动无关）；frontmatter 与文件引用路径保持不变。

## V2.0

- 将超长单体提示词拆分为调度层、规则层、模板层、校验层和渲染层；
- 新增事实证据台账、需求响应矩阵、课程设备空间映射、实施验收矩阵；
- 删除静态赛事状态结论，改为项目级动态核验；
- 将“首个/领先”改为高风险主张；
- 将固定三方自评改为确定性校验 + 文类自适应专家评审；
- 删除直接 XML 字符串替换作为标准修改流程；
- 用 Pandoc 解析 Markdown，避免表格静默丢失；
- 新增 Word 渲染、反馈提取、版本对比和流水线工具；
- Word 构建在缺失源文件或工具时显式失败，不回退到示例方案。

## V2.1（2026-07-27，基于华南师大附中智慧能源实验室项目复盘）

按"先逐条确认、再修改"的方式，根据一次完整售前方案过程暴露的通用问题优化：

- **节点确认机制**：新增 SKILL.md §2.4，支持 `confirmation_mode`（full/core/each），默认在关键产物给出摘要请用户确认；workflows 各阶段末增加"输出摘要请确认"步骤；阶段 0 "直接继续"改为受确认模式约束。
- **构建可靠性**：build_docx.py 新增 `--overwrite`（覆盖写同名输出并自动备份旧版为 `_备份_时间戳`），消除"时间戳→后处理→改名"的脆弱流程。
- **字体与缩进内建**：build_docx.py 集成 `output.font`（默认微软雅黑）与 `output.first_line_indent`（默认 2 字符），统一应用到正文、表格单元格与页眉页脚（此前表格单元格会掉字体，且需临时脚本后处理）。
- **渲染降级**：render_review.py 在 LibreOffice/soffice 不可用时自动执行结构化降级验收（非视觉渲染），并标注须人工复核版式。
- **文档完整性硬门槛**：validate_project.py 新增 STAGE_DOC_EMPTY（01/02 空模板→error）与 STAGE_DOC_THIN（其余阶段文档偏薄→warning）。
- **封面标签可配**：project.yaml `confidentiality` 改为按交付对象选择、可留空不显示（默认客户交流版，替代固定"内部资料"）。
- **外部权威文件**：新增 `project.external_authoritative`，SKILL.md §2.2 明确其作为设备命名/价格唯一来源、Word 仅概念引用、旧清单标注"参考样例/作废"。
- **客户交付红线**：writing_guide.md 增补"面向客户的交付红线"（学校文化自然融入不贴标签、参考图不提他校、无内部口径、价格集中归预算章、整段叙述为主）。
- **内容充实与借鉴**：writing_guide.md 新增第 10 节，明确"借充实度不借格式与名称、不引入未核实事实"。

## V2.2（2026-07-27，固化 grill-me 需求澄清机制）

将全局"先问清需求再执行"规则固化进 skill，作为无条件强制铁律：

- **需求澄清机制（grill-me）**：SKILL.md 新增 §2.4——任何项目开始执行前必须先完成 grill-me 式澄清，一次一问、至 95% 把握才动手；阶段 0 强制澄清，后续阶段缺漏才问。原"节点确认机制"顺延为 §2.5，并新增输入端/输出端交叉引用。
- **workflow 加澄清步骤**：workflows/01 第 2 步新增 grill-me 强制澄清（含澄清要点清单），后续步骤相应顺延，并补"后续阶段缺漏才问"说明；§2.4→§2.5 引用同步改号。
- **新增 references/grill_me_guide.md**：适用判定、一次一问核心规则、从方向到边界的追问策略、话术示例、95% 把握判定标准、与节点确认机制的配合关系；SKILL.md §8 资源索引已登记。

## V2.3（2026-08-01，新增正式方案去 AI 味能力）

目标：让方案读起来更专业、更有真人感，但不滑向口语化闲聊体。

- **阶段 6.5 专业表达检验（去 AI 味门禁）**：在 SKILL.md 阶段 6（确定性校验）与阶段 7（专家评审）之间新增语言净化门禁；workflows/03 同步插入处理步骤。
- **新增 references/formal_dereification.md**：正式文风去 AI 味规则源。复用通用去 AI 味的**检测目录**（最毒句式/客套开场结尾/模板过渡/模糊限定/官腔空话/无证据强词/空泛修饰/机械化连接词），但**刻意不套用其口语化注入配方**（口语锚点、语气词、句子碎片、用"我"的体验、戛然而止、删冒号/破折号/双引号），以保留正式文档的庄重、有据与节奏。
- **validate_project.py 集成 check_formal_ai_tells()**：扫描 `07_方案终稿.md`，以 warning 级产出 `AI_TELL_*` / `AI_TELL_FILLER` / `AI_TELL_CONNECTOR` 项，进入 `qa/validation_report.json` 与 `.md`；不阻断交付（语言润色非一票否决）。
- **writing_guide.md §9** 增加交叉引用，使交付前语言检查与自动扫描口径对齐。

> 设计取舍：未采用"直接调用现有 de-ai skill"方案——其注入活人感配方会令政府申报/建设方案显得像微信闲聊，反而损害专业性；故走"检测复用 + 正式文风重写"路线。未做阶段 7 评审角色→专家包的拆解（本次仅优化去 AI 味）。
